The hybrid

It is not any one of the four reference models

Between the gateway and the worker there is exactly one contract: a URL string on the key camera:transport:<id>. The worker imports no gateway code; the gateway knows no model. That seam is what lets a new vendor arrive as one driver file.

Prahari04 / 10 · Video analytics — ANPR

The mandatory analytic

The pipeline, and the record it produces

Frame (PTS)decoded at 5 fps
Vehicle detectYOLOv8s · batch 16 · 20 ms flush
TrackByteTrack, one per camera
Plate detectinside the vehicle crop
Two readersEasyOCR + PaddleOCR
Grammar + voteper-character, refuses below 2/3

Plate detection runs on the vehicle crop, not the frame: a 20 px plate in a 1920 px frame is ~7 px after letterboxing; inside a 300 px crop it is a readable band. Grammar (^[A-Z]{2}[0-9]{2}[A-Z]{1,3}[0-9]{4}$, BH series too) is applied before the vote, so the vote spends itself only on genuine ambiguity.

Prahari06 / 10 · Watchlist correlation & alerts

Real-time alerts

Banded matching, an audited state machine

Matching is banded, not binary: exact plate_norm, then plate_canon (confusion classes collapsed), then weighted edit distance ≤ 1.0. Watchlist categories: stolen vehicles, wanted / missing persons, blacklisted vehicles, suspect lists.

NEW→ ACK→ IN_PROGRESS→ RESOLVED | FALSE_POSITIVE

Every transition is written to the audit log with a user and a reason. Repeated sightings of one vehicle bump a count on the open alert — twenty alerts for one event is how an operator learns to ignore them.

Prahari07 / 10 · The graded test case

Route reconstruction

A registration number in. A defensible route out.

A judge types a vehicle registration; the map draws that vehicle's hops across the grid with timestamps and locations, snapped to roads via OSRM.

What it returns

  • Ordered hops: camera, coordinate, timestamp
  • Implied speed on each leg
  • CSV export, audited

What it refuses

  • A hop needing 180 km/h through a city is flagged IMPLAUSIBLE, not quietly drawn
  • A route that cannot lie to an officer is worth more than one that always answers

Expected output for the jury: complete route, timestamped and location-wise, plus the live watchlist cross-referencing and auto-alerts running alongside it.

Prahari08 / 10 · Security & accountability

RBAC + audit

Enforced in SQL. Hiding a button is not access control.

The department-scope matrix is enforced in the database with row-level security as the backstop — not in the UI. A district viewer's query simply returns fewer rows; a system administrator may not see live data at all.

Every action is logged

  • Every export and every live view writes an audit row
  • Cross-department access needs a case number, a 72 h cap and target-department approval
  • The log is hash-chained; a tamper breaks the chain

Integration-ready

  • APIs shaped for VAHAN, SARTHI, eGujCop (CCTNS), AFIS, NAFIS
  • Documented, open protocols — no lock-in on cameras, VMS, analytics or storage

Prahari09 / 10 · Scalability & PoC readiness

The arithmetic, printed so the jury can check it

Four orders of magnitude, in four multiplications

Centralised video — the M4 approach we reject:

80,000 cameras × 2 Mbps (H.264, 720p, 5 fps) = 160,000 Mbps ≈ 160 Gbps 160 Gbps × 86,400 s/day ≈ 1.7 PB/day ≈ 26 PB at ~15-day retention

Metadata — what we actually ship:

~200 bytes per sighting row ([C1]) 80,000 cameras × ~1,000 sightings/camera/day ≈ 80 M rows/day 80 M × 200 B ≈ 16 GB/day raw ≈ 2–3 GB/day compressed (Timescale)

26 PB → 16 GB/day. That is the entire case for edge inference.

Scale plan also covers: central / regional / edge compute, GPU sizing, low-bandwidth operation, hot / warm / cold storage by retention, HA, backup, DR, cybersecurity, and a capex + opex estimate.
